# Daily Wallpaper

Daily Wallpaper 是一个 macOS 13+ 原生 AppKit 壁纸应用。它提供标准前台主窗口，并保留菜单栏快捷入口，用于下载和应用允许作为壁纸使用的必应每日图片、管理多显示器规则，以及浏览和导入本地图片。

应用面向长期后台运行场景设计：不引入第三方依赖，不做周期轮询，下载和哈希均采用流式处理；主窗口关闭后应用继续在菜单栏运行，并立即释放页面控制器、媒体库分页数据、预览任务和内存缩略图缓存。后台仍保留菜单栏、SQLite 单连接、事件监控、更新协调器及必要的设置状态。

## 下载与安装

[下载最新版本](https://github.com/hdheid/daily-wallpaper/releases/latest) | [查看全部版本](https://github.com/hdheid/daily-wallpaper/releases) | [发布指南](RELEASE.md)

GitHub Release 提供同时支持 Apple Silicon 和 Intel Mac 的 `DailyWallpaper-vX.Y.Z-macOS-universal.zip`，以及对应的 SHA-256 校验文件。当前自动发布产物是包含 `.app` 的 ZIP，不是 DMG。

1. 从 Releases 页面下载 ZIP 和同名 `.sha256` 文件。
2. 在两个文件所在目录执行校验：

   ```bash
   shasum -a 256 -c DailyWallpaper-vX.Y.Z-macOS-universal.zip.sha256
   ```

3. 解压 ZIP，将 `DailyWallpaper.app` 移动到“应用程序”目录。
4. 首次启动如被 macOS 拦截，右键 App 选择“打开”，或前往“系统设置 -> 隐私与安全性”确认打开。

当前下载版本使用 ad-hoc 签名，尚未使用 Developer ID 证书，也没有经过 Apple 公证，适合体验和自用。

## 已实现功能

- 标准 macOS 前台应用身份，显示 Dock 图标、Command-Tab 入口和系统应用菜单。
- 单一主窗口集成“媒体库”“显示器”“下载目录”“自动化”四个页面。
- 侧栏页面使用原子即时替换：目标页准备完成后再切换并释放旧媒体库，避免残留筛选栏、空白页或导航状态错位。
- 主窗口工具栏提供“下载今日图片”“下载并应用”“导入图片”快捷操作。
- 保留原生 `NSStatusItem + NSMenu` 菜单栏入口；关闭主窗口不会退出应用，可从 Dock 或菜单栏重新打开。
- 自动识别当前显示器数量、名称、主屏、Display UUID 和实际像素分辨率。
- 支持全部显示器相同配置，以及按显示器独立设置市场、分辨率、缩放方式和自动更换开关。
- 设置页使用居中的 `820pt` 最大阅读列；共享模式隐藏单屏专属控件，规则与保存操作收进同一张玻璃卡片，最小窗口下可纵向滚动而不会裁切。
- 每日自动下载与每日自动更换分开控制，并阻止“只自动更换、不自动下载”的无效组合。
- 获取必应最近 8 张图片，只选择明确满足 `wp == true` 的条目。
- UHD 下载失败后自动回退到服务端原始图片地址。
- 默认归档到 `~/Pictures/dailywallpaper`，支持 security-scoped bookmark 自定义目录。
- 按 `年/月/日/国家或标签/实际分辨率` 归档原图和同名 JSON 元数据。
- 同一张必应图片在不同国家返回不同标题或介绍时，会保留各自独立的国家目录、旁车 JSON 和媒体库记录，不再按图片 SHA 互相覆盖。
- 使用 1 MB 分块 SHA-256 去重，不把完整原图加载进内存。
- 支持 JPEG、PNG、HEIC、TIFF、WebP 外部图片和文件夹递归导入。
- SQLite WAL 索引、80 条 keyset 分页、来源/地区/分辨率/搜索/日期排序。
- 媒体库内提供“媒体库 / 今日壁纸”分页；今日页可按中国、美国、日本、德国和法国查看当天已经下载入库的必应图片。
- AppKit 瀑布流媒体库，只为可见项和少量预取项生成缩略图。
- 媒体库顶部按已连接显示器展示当前壁纸缩略图、主屏标记和核验状态；状态来自当前 Space 的系统实际壁纸 URL，而不是只读取应用历史记录。
- 当前壁纸媒体卡会标记具体显示器；外部修改系统壁纸后会显示为“系统外部壁纸”。
- 双击媒体卡进入应用内大图预览，支持横向胶片条、方向键、Esc、跨分页继续浏览和悬停标题/介绍。
- 预览大图按 Retina 窗口尺寸有界降采样，ImageIO 解码由 actor 串行执行，快速切换或关闭时会取消待处理任务。
- Quick Look 缩略图并发最多 2，内存缓存 32 MB，磁盘缓存预算 256 MB。
- 切离媒体库页面时暂停查询并释放图片列表和缩略图缓存，返回后重新按页加载。
- 右键支持使用系统应用打开原图、访达定位，以及设置到全部或指定显示器。
- 更新结果和媒体库加载反馈使用不拦截鼠标的玻璃 Toast，并通过 VoiceOver announcement 播报；界面尊重系统“减弱动态效果”。
- 使用 `SMAppService.mainApp` 控制登录时启动。
- 监听跨日、唤醒、Session 激活、时区、时钟、屏幕和 Space 变化，不做周期轮询。
- 失败重试为 15 分钟、1 小时、3 小时三个带容差的单次 Timer。
- 网络会话按更新批次懒创建，批次结束后释放；应用退出后进入终态，不会重新建立连接。
- SQLite 写入失败时使用小型持久待索引队列恢复；升级到 v2 时只对每个已登记目录执行一次串行旁车 JSON 扫描，以恢复旧索引覆盖掉的国家记录。

## 构建

要求：macOS 13+，以及 Xcode 26 或兼容的 Swift 6 工具链。

```bash
./Scripts/build.sh
```

默认构建 Release，产物位于：

```text
.build/Build/Products/Release/DailyWallpaper.app
```

本机没有 Developer ID 证书时，脚本使用 ad-hoc 签名，仅适合本机自用。登录启动 API 要求应用已签名；正式跨机器分发还需要 Developer ID 证书和公证。

本机安装可将构建产物复制到 `/Applications`，再从访达启动。启动后会出现 Dock 图标、主窗口和菜单栏图标。首次启动如被系统安全策略拦截，请在“系统设置 -> 隐私与安全性”中确认打开。公开下载版本同样使用 ad-hoc 签名，可用于体验和自用，但尚不是经过 Apple 公证的正式分发包。

## GitHub 自动发布

仓库包含 tag 驱动的 GitHub Actions 工作流。推送 `vX.Y.Z` 格式的 tag 后，GitHub 会自动：

- 运行全部 XCTest。
- 将 tag 版本写入 App 的 `CFBundleShortVersionString`。
- 构建包含 `arm64 + x86_64` 的通用架构 Release。
- 校验 App 签名，生成 ZIP 和 SHA-256 校验文件。
- 创建对应版本的 GitHub Release，并上传两个下载文件。

发布新版本示例：

```bash
git tag -a v0.2.0 -m "发布 v0.2.0"
git push origin v0.2.0
```

当前工作流使用 ad-hoc 签名，没有 Developer ID 证书和 Apple 公证。其他用户首次打开下载的 App 时，可能需要右键选择“打开”，或在“系统设置 -> 隐私与安全性”中确认。仓库已经公开，任何人都可以访问 Release 并下载构建产物。完整发布流程见 [RELEASE.md](RELEASE.md)。

## 使用

首次正常启动后，应用会打开“媒体库”主页面。左侧栏可切换显示器、下载目录和自动化设置；工具栏可直接下载、下载并应用或导入图片。显示器和自动化选项先写入页面草稿，保存前不改变持久配置；点击“保存更改”后一次性提交并触发一次配置重评。是否下载或更换仍由每日开关、当天缓存和显示器规则共同决定。目录选择、恢复和移除属于文件授权操作，仍会即时生效。默认会检查当日图片；如果当前必应最近 8 张都不是 `wp == true`，应用会保留原壁纸并显示失败原因。

媒体库顶部的“今日壁纸”页只读取本地当天已下载的必应记录，可继续按国家、分辨率和标题筛选；切换国家不会主动联网，也不会下载未配置国家的图片。同一图片若被多个国家返回，每个国家仍显示自己的标题和介绍。

关闭主窗口后应用不会退出，菜单栏下载、自动化与系统事件监听仍继续工作。此时媒体库页面、分页任务和内存缩略图缓存已经释放。点击 Dock 图标，或从菜单栏选择“打开媒体库”“设置”，会重新创建主窗口并打开对应页面。

菜单提供当前壁纸缩略图、立即下载、立即下载并更换、媒体库、外部导入、下载目录、当前图片、两个每日开关、设置、登录启动和退出。

## 手工 UI 验收

以下项目需要在真实桌面环境中由用户执行；自动验证没有代替操作用户壁纸：

1. 单屏启动，确认出现 Dock 图标、菜单栏图标和标准主窗口。
2. 确认侧栏包含“媒体库”“显示器”“下载目录”“自动化”，切换时内容与选中状态一致。
3. 确认工具栏的下载、下载并应用和导入入口可用；任务忙碌时相应工具栏与应用菜单命令会禁用。
4. 将主窗口缩到最小 `1000 x 600`，确认筛选栏和目录长路径没有重叠；显示器独立模式内容可纵向滚动，规则与保存区均无不可读裁切。
5. 关闭主窗口，确认应用仍在菜单栏运行；分别用 Dock 和菜单栏重新打开，并确认回到可用页面。
6. 从媒体库首次直接进入显示器、下载目录和自动化，并在四页间快速往返；确认不残留媒体库筛选栏、不出现空白设置页，返回媒体库后重新分页加载且快速滚动不串图。
7. 确认媒体库顶部按每台显示器展示当前 Space 的实际壁纸、主屏标记和核验状态；从系统设置手工换图后应显示“系统外部壁纸”。
8. 确认显示器名称、主屏标记和像素分辨率正确，当前壁纸媒体卡标出具体显示器。
9. 双屏下分别编辑“全部显示器相同”和“每个显示器独立”，确认保存前不生效、点击“保存更改”后只触发一次配置重评。
10. 在自动化页关闭每日更换但保留每日下载，保存后确认只新增归档、不改变壁纸。
11. 关闭每日下载，确认每日更换同时关闭；手动操作仍可用。
12. 选择自定义目录，重启后确认授权和路径仍有效；下载或导入过程中确认目录切换和历史目录移除入口均被禁用。
13. 导入多张图片和包含子目录的文件夹，确认重复、隐藏文件、不支持格式和取消统计；导入中工具栏、应用菜单、菜单栏和媒体库空态导入入口均应禁用。
14. 验证媒体库首次 80 条、滚动分页、筛选、搜索、瀑布流重排和快速滚动不串图。
15. 进入“今日壁纸”，依次切换中国、美国、日本、德国和法国；确认只显示本地当天记录，同图不同国家仍保留各自标题和介绍。
16. 双击图片进入应用内预览，确认胶片条、悬停标题/介绍、方向键、Esc 和跨越首批 80 条的继续分页都可用；快速切换不显示旧图。
17. 右键从媒体库打开原图、访达定位，并把图片分别设置到全部显示器和指定显示器。
18. 确认玻璃 Toast 不拦截底部卡片点击和滚动；使用 VoiceOver、全键盘访问及“减弱动态效果”核验提示和控件语义。
19. 切换 Space、插拔显示器和睡眠唤醒，确认状态带刷新、只重应用本地缓存且没有高频网络访问。

## 资源约束

- 空闲时没有应用自建的周期 Timer 或文件系统监听器。
- URLSession 每个主机最多一个连接，每批更新结束后释放，下载正文直接写临时文件。
- 下载校验和导入检查路径的 ImageIO 只读文件头与元数据；菜单栏最多缓存一张 480 像素当前壁纸缩略图，应用内预览只串行解码一张有界降采样图。
- 导入串行处理文件，哈希缓冲固定为 1 MB。
- v2 升级恢复按目录串行读取小型旁车 JSON，不读取完整图片，并每处理 32 条主动让出执行权；每个目录成功完成后不再重复扫描。
- 媒体库每页只读 80 条；切离页面或关闭主窗口会取消分页、facet 和预取任务，并清空 32 MB 内存缓存。
- 主窗口关闭后会释放全部主窗口页面及其 UI 图片资源；菜单栏最多保留一张 480 像素当前壁纸缩略图。后台还会保留 SQLite 单连接、事件监控、更新协调器、目录/显示器/设置状态，失败时可能保留一个低频单次重试 Timer；正在执行的下载或导入任务按自身生命周期结束。

资源测试时必须禁止启动阶段联网和更换壁纸：

```bash
DAILY_WALLPAPER_DISABLE_STARTUP_UPDATE=1 \
  .build/Build/Products/Release/DailyWallpaper.app/Contents/MacOS/DailyWallpaper
```

2026-07-27 曾对上一版 `LSUIElement=true` 的纯菜单栏 Release 做过空闲采样：CPU 连续 20 个样本为 `0.0%`、物理 footprint 为 `12 MB`、`ps` RSS 为 `46,864 KB`。这些数字只是历史基线，不是当前 `LSUIElement=false` 前台主窗口版的实测结果。

每个自动发布的 Release 都附带独立 SHA-256 校验文件。最新版的主窗口打开、主窗口关闭后台常驻、媒体库滚动和批量导入资源数据尚未重新采样，应在真实 UI 验收时分别记录；其中旧版 RSS 已高于原设计的 `40 MB` 上限，不能用 footprint 替代该结论。

## 已知系统边界

- Bing `HPImageArchive.aspx` 是未正式版本化的内部端点，字段和 UHD 地址规则未来可能变化。
- `mkt` 只是市场偏好，Bing 可能根据网络出口覆盖返回地区。
- macOS 公共 API 不能一次枚举并设置所有 Space；应用会在 Space 被激活时同步当前本地壁纸。
- 当前产物是本机 ad-hoc 签名版本，没有执行 Developer ID 分发和公证。
- macOS 26.5.2 创建标准关闭、最小化和缩放按钮时，私有 `ThemeWidgetControlViewService` 会各记录一次负尺寸 runtime issue。A/B 已确认移除三颗系统按钮后日志为 0，而禁用窗口恢复或移除自定义工具栏项不改变结果；为保留标准窗口功能，本项目不绕过系统按钮。
- 已用 Computer Use 完成双屏媒体库、四页快速切换、双击预览、胶片条点击、方向键和 Esc 的只读回归；没有点击下载、应用、导入或保存。悬停动画、真实壁纸切换、高负载媒体库和最新版资源数据仍由用户按上面的清单验收。
